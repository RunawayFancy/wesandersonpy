# Security policy

## Supported versions

Before the first release, security fixes are made on the `main` branch. After publishing begins, the latest minor release series will receive security fixes; this table will then be updated with explicit supported versions.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue. Once the GitHub repository is configured, use its private vulnerability-reporting feature. Until then, contact the maintainers privately through the same channel by which you received the source.

Include the affected version or commit, a minimal reproduction, impact, and any suggested mitigation. Do not include credentials, confidential datasets, or third-party personal information. Maintainers will acknowledge receipt, assess the report, coordinate a fix, and credit the reporter if requested and appropriate.

GitHub's private vulnerability reporting documentation was last reviewed on 2026-08-23: <https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/privately-reporting-a-security-vulnerability>.
